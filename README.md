# VulnLab — Лабораторная работа №2

## Описание проекта

**VulnLab** — учебное Python веб-приложение, разработанное для демонстрации двух распространённых уязвимостей веб-приложений из списка OWASP Top 10.

В рамках лабораторной работы реализованы:
- SQL Injection (SQL-инъекция).
- IDOR (Insecure Direct Object Reference).

Также разработан отдельный Python-скрипт для демонстрации эксплуатации уязвимостей и подготовлен патч для их устранения.

Приложение работает локально и использует SQLite для хранения данных.

## Используемые технологии

- Python 3.
- SQLite.
- HTTP Server (`http.server`).
- `urllib` для отправки HTTP-запросов.
- Git для применения патча.

Проект не требует установки сторонних Python-библиотек.

## Структура проекта

```text
VulnLab/
│
├── server.py      # Исходный код уязвимого веб-сервера
├── exploit.py     # Скрипт демонстрации эксплуатации
└── patch.diff     # Патч для устранения уязвимостей
```

База данных SQLite создаётся автоматически при первом запуске сервера.

## Реализованные уязвимости

### 1. SQL Injection

**Категория OWASP: A03 — Injection**

Уязвимость находится в механизме авторизации пользователей.

SQL-запрос формируется путём объединения SQL-команды с пользовательским вводом. Это позволяет изменить логику запроса и обойти проверку пароля.

**Исправление:**

Использование параметризованных SQL-запросов с передачей пользовательских данных отдельно от SQL-команды.

### 2. IDOR

**Категория OWASP: A01 — Broken Access Control**

Уязвимость находится в механизме получения пользовательских заметок.

Приложение проверяет наличие авторизованной сессии, но не проверяет, принадлежит ли запрашиваемая заметка текущему пользователю.

В результате пользователь может получить чужую заметку, изменив её идентификатор в HTTP-запросе.

**Исправление:**

Добавление проверки владельца заметки. Теперь сервер возвращает запись только в том случае, если она принадлежит авторизованному пользователю.

## Запуск приложения

### Требования

- Установленный Python 3.
- Операционная система Windows, Linux или macOS.

### Шаг 1. Запуск сервера

Откройте терминал в папке проекта и выполните:

```bash
python server.py
```

После запуска приложение будет доступно по адресу:

http://127.0.0.1:8000

При первом запуске автоматически создаётся база данных с двумя тестовыми пользователями.

| Логин | Пароль |
|---|---|
| alice | alice123 |
| bob | bob123 |

### Шаг 2. Демонстрация эксплуатации

Не закрывая сервер, откройте второй терминал в папке проекта и выполните:

```bash
python exploit.py
```

Скрипт автоматически выполняет два действия:

1. Демонстрирует SQL Injection путём отправки специально сформированного HTTP-запроса авторизации.
2. Демонстрирует IDOR, запрашивая заметку другого пользователя после успешной авторизации.

При успешной эксплуатации скрипт выводит полученный HTTP-ответ и содержимое чужой заметки.

## Устранение уязвимостей

Для исправления ошибок подготовлен файл `patch.diff`.

Перед применением патча остановите сервер сочетанием `Ctrl+C`.

Выполните команду из корневой папки проекта:

```bash
git apply patch.diff
```

Патч вносит следующие изменения:

- Заменяет небезопасное формирование SQL-запроса параметризованным запросом.
- Добавляет проверку принадлежности заметки текущему пользователю.
- Предотвращает получение чужих данных через изменение идентификатора заметки.

После применения патча файл `server.py` будет содержать исправленную версию приложения.

## Проверка исправлений

После применения патча повторно запустите сервер:

```bash
python server.py
```

В другом терминале запустите скрипт эксплуатации:

```bash
python exploit.py
```

Ожидаемый результат:

- SQL Injection больше не позволяет обойти авторизацию.
- Чужая заметка не возвращается сервером.
- Пользователь может получать только собственные заметки.

## Меры безопасности

Данный проект предназначен исключительно для учебных целей.

Уязвимая версия приложения намеренно содержит ошибки безопасности. Запускайте её только локально, не открывайте доступ к ней из интернета и используйте исключительно тестовые данные.

## Вывод

В ходе лабораторной работы разработано локальное веб-приложение на Python, содержащее две намеренные уязвимости: SQL Injection и IDOR.

С помощью отдельного Python-скрипта продемонстрирована эксплуатация данных уязвимостей посредством HTTP-запросов.

Для устранения обнаруженных проблем разработан патч в формате diff. Исправления основаны на использовании параметризованных SQL-запросов и проверке прав доступа к пользовательским данным.

Таким образом, были рассмотрены причины возникновения двух распространённых уязвимостей веб-приложений, способы их эксплуатации и методы устранения.
